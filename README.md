# The Guardian of Kali — Backend (`kali-ai-backend`)

Backend service and policy engine for **The Guardian of Kali**, an AI-assisted desktop terminal environment designed for ethical hacking practice (CTFs, HackTheBox, TryHackMe, and local labs) hosted on Kali Linux via WSL2.

## Architecture

This project is strictly structured using **Clean Architecture** principles across four layers:

- **Domain (`src/domain/`)**: Pure entities, domain models, and zero-dependency business rules.
- **Application (`src/application/`)**: Use cases, command orchestration, and abstract port interfaces.
- **Adapters (`src/adapters/`)**: Concrete implementations of interfaces (Claude API client, system runners, loggers).
- **Infrastructure (`src/infrastructure/`)**: Framework configurations, FastAPI routes, and external system integrations.

Dependencies always point inwards toward the Domain layer.

## Security Model

The backend interacts with Kali Linux on WSL2 using two distinct operating system accounts:
1. **Operator User**: Unrestricted interactive user for manual operation.
2. **Restricted AI User (`ia-user`)**: Execution user with no default `sudo` privileges and strict whitelist policies.

Every command generated by the AI must pass through the **Policy Engine** (blacklist filter, risk classification, and authorized target scope check) prior to execution. This security gate can never be bypassed.

## Tech Stack

- **Runtime**: Python 3.11+
- **API Framework**: FastAPI + Uvicorn
- **AI Integration**: Anthropic Claude API (Tool Use / Function Calling)
- **Environment**: WSL2 (Kali Linux)
- **Quality & Testing**: Pytest, Ruff, Mypy
